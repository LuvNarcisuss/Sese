# Sese iOS project

- The product display name, Xcode project, app target, and shared scheme are Sese. Debug uses the purchase acceptance Bundle ID `im.seex.sao2` and Yu Sun team `JPTS6M4T5B`. Release uses `com.sese.citycommunit`; distribution signing awaits owner configuration. The UI test target uses `com.sese.citycommunit.uitests`.
- Keep the selected Bundle ID, device account alias domain, and wallet directory stable across display name changes. The new Bundle ID uses a separate app container and device credential from earlier builds.
- Native UIKit, Swift 5, AVFoundation, iOS 16+, iPhone only and portrait. Keep project.yml and the generated Xcode project aligned.
- The five tabs are Shorts, Districts, Cosplay, Chats and Me. Use original ImageGen raster UI art and bundled custom typography. Credit editorial media in the application and in Docs/Media.md.
- Store original artwork and licensed editorial media in the dedicated Supabase Storage project. Keep image and video binaries out of the working tree and Git. Xcode fetches the launch icon as an ignored build input. When changing media, follow Docs/Media.md for attribution and verification.
- Shorts pages through licensed 9:16 MP4s hosted in the dedicated Supabase Storage project. Loop the visible clip with AVPlayer behind the toolbar and translucent tab bar. Keep the avatar and video actions above the tab bar, with clip information and credits at the lower left. Preserve stable catalog IDs for existing interactions. Keep publisher links for attribution and existing catalog details.
- Use this project's dedicated Supabase instance and device-based one-tap sign-in. Use one sign-in button, a separate unchecked consent box, and inline links to both agreements. Keep Supabase anonymous sign-ins disabled. See Docs/Backend. Keep member records separate from editorial material. Never seed member accounts or member activity or claim delivery before an acknowledged write. Owner-approved prepared discussions use explicit editorial attribution and counts derived from stored comments.
- Use transparent, fixed-size icon targets in main-page toolbars and the Shorts action column. Like and Save must retain the same visible artwork dimensions in both toggle states; equal button bounds alone are insufficient when the source images have different transparent margins. Use recognizable credited photo portraits and make publisher and member avatars independent profile links.
- New accounts start with empty collections, relationships and chats. Chats starts with real mutual friends or a heading and invitation card when there are none. Conversations and Archived keep existing history accessible. The chat rule is mutual following. Block and report actions must remain accessible.
- Districts opens on the free City Center map. Use the existing account-scoped device wallet for one-time district unlocks and district construction. Save each debit and its unlock or district in a single wallet write. Keep built districts and exploration progress local to the signed-in account on this device. Catalog IDs and existing saves remain available.
- Cosplay photo and video files use public links. Upload and removal require the owner's account. Explain link visibility before submission. New posts enter manual review; only approved posts from eligible members appear in the community gallery. Preserve existing link submissions and their identifiers.
- The wallet uses the Sese consumables in `App/CommunityContent/Products.json` and account-bound, verified, idempotent delivery. StoreKit supplies displayed prices. Keep `Configuration/SeseDiamonds.storekit` aligned with the catalog and selected for the shared scheme's Debug Run. Use StoreKit Configuration None when checking the Apple sandbox catalog.
- Do not compile, typecheck, launch, run a simulator or run app tests without explicit owner authorization. Static checks and XcodeGen metadata generation are allowed.
- Run authorized simulator acceptance only on `Sese UI Acceptance` (iPhone 17 Pro). Build the current workspace, install and launch that build on the named device, and disable parallel UI testing so Xcode uses that device without clones. Leave the latest build running there after testing. Report any blocked step instead of using another device or an older build.
- App-owned and project content is English.
