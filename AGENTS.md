# Sese iOS project

- The product display name, Xcode project, app target, and shared scheme are Sese. Debug and Release use `com.sese.citycommunit`. Leave the development team unset until the owner provides a signing team. The UI test target uses `com.sese.citycommunit.uitests`.
- Keep the selected Bundle ID, device account alias domain, and wallet directory stable across display name changes. Changing the Bundle ID creates a separate app container and device credential.
- Native UIKit, Swift 5, AVFoundation, iOS 16+, iPhone only and portrait. Keep project.yml and the generated Xcode project aligned.
- The five tabs are Shorts, Districts, Cosplay, Chats and Me. Use original ImageGen raster UI art and bundled custom typography. Credit editorial media in the application and in Docs/Media.md.
- Store original artwork and licensed editorial media in the dedicated Supabase Storage project. Keep image and video binaries out of the working tree and Git. The owner-supplied launch icon is the exception: its text-encoded source is tracked in Configuration/AppIcon.base64, and Xcode reconstructs the ignored PNG with SHA-256 verification. Do not restore the superseded remote launcher. When changing media, follow Docs/Media.md for attribution and verification.
- Shorts pages through licensed 9:16 MP4s hosted in the dedicated Supabase Storage project. Loop the visible clip with AVPlayer behind the toolbar and translucent tab bar. Keep the avatar and video actions above the tab bar, with clip information and credits at the lower left. Preserve stable catalog IDs for existing interactions. Keep publisher links for attribution and existing catalog details.
- Use this project's dedicated Supabase instance and device-based one-tap sign-in. Use one sign-in button, a separate unchecked consent box, and inline links to both agreements. Keep Supabase anonymous sign-ins disabled. See Docs/Backend. Keep member records separate from editorial material. The original eight hosted Shorts belong to four app-managed community publishers. Three additional Shorts belong to existing discussion profiles. All these accounts have sign-in disabled. Each new Short uses a different original film. Their avatars open the shared member profile, whose More menu offers Report user and Block user for other accounts. Preserve the original clip credits. The 93 prepared discussion entries are distributed across eight owner-approved editorial desks in each of the four original Shorts with distinct nicknames, credited portraits and sign-in disabled. Each editor uses a different source photograph, independent of all video frames. Bylines show the plain nickname and open the shared profile by account ID. These eight profiles have empty bios and use the standard member profile layout. Preserve each comment ID, key and body. Do not seed other accounts or member activity or claim delivery before an acknowledged write. Discussion counts derive from visible stored comments.
- Use transparent, fixed-size icon targets in main-page toolbars and the Shorts action column. All app-owned navigation, toolbar, action, wallet, and consent icons use the shared 40-by-40-point visible footprint within 48-point icon touch targets. The Shorts avatar uses that same footprint. More uses three horizontal enamel dots. Comment More artwork follows the body font size inside a 48-point target at the top right. App-owned dialogs use the illustrated night skyline. Follow and Message share the full row equally at standard text sizes with a compact 44-point height, and profile categories use display lettering with a selected underline. Source padding is normalized centrally; backgrounds, maps, photos, and large profile portraits remain content imagery. Like and Save retain that footprint in both toggle states; equal button bounds alone are insufficient when the source images have different transparent margins. Use recognizable credited photo portraits and make publisher and member avatars independent profile links.
- New accounts start with empty collections, relationships and chats. Chats starts with real mutual friends or a heading and invitation card when there are none. Conversations and Archived keep existing history accessible. The chat rule is mutual following. Block and report actions must remain accessible.
- Successful video reports hide that video for the reporting account immediately and on subsequent reads. A member block separately hides all content from that author, including comments from private profiles. Settings shows identifiable, privacy-safe records with confirmed long-press undo and an accessible tap alternative. Undo only the selected action, preserve moderation evidence, and restore only otherwise eligible content. Reporting a comment hides only that comment and updates the visible count. Settings lists reported comments with confirmed withdrawal. Identify the selected target in both the report reason picker and its dismissible success alert. Quote the selected comment when reporting a comment, and use the visible nickname for reports and blocks of a member. Show success only after the write is acknowledged. After a block, return to the preceding eligible screen and show the acting account one success alert. Reports and blocks are silent for the targeted member. Keep moderation records available to authorized operators.
- Districts opens on the free City Center map. Use the existing account-scoped device wallet for one-time district unlocks and district construction. Save each debit and its unlock or district in a single wallet write. Keep built districts and exploration progress local to the signed-in account on this device. Catalog IDs and existing saves remain available.
- Cosplay photo and video files use public links. Upload and removal require the owner's account. Explain link visibility before submission. New posts enter manual review; only approved posts from eligible members appear in the community gallery. Preserve existing link submissions and their identifiers.
- The wallet uses the Sese consumables in `App/CommunityContent/Products.json` and account-bound, verified, idempotent delivery. StoreKit supplies displayed prices. Keep `Configuration/SeseDiamonds.storekit` aligned with the catalog and selected for the shared scheme's Debug Run. Use StoreKit Configuration None when checking the Apple sandbox catalog.
- Do not compile, typecheck, launch, run a simulator or run app tests without explicit owner authorization. Static checks and XcodeGen metadata generation are allowed.
- Run authorized simulator acceptance only on `Sese UI Acceptance` (iPhone 17 Pro). Build the current workspace, install and launch that build on the named device, and disable parallel UI testing so Xcode uses that device without clones. Leave the latest build running there after testing. Report any blocked step instead of using another device or an older build.
- Scrollable data screens support pull-to-refresh, including empty lists. A drag over a button or card must still scroll. Finish feedback follows all relevant requests; preserve filters, drafts, and existing data on failure. See Docs/PullRefreshVerification.md for route-specific behavior and actual coverage.
- App-owned and project content is English.
