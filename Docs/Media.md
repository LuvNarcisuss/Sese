## Storage and build delivery

- The two gallery photos and 21 generated images are stored in Sese's `editorial` bucket. The gallery, member avatar choices, and interface artwork load over HTTPS with an in-memory image cache. Chat attachments use the private `chat-photos` bucket.
- The Xcode target decodes `Configuration/AppIcon.base64` and verifies the launcher SHA-256 in `Docs/Artwork.json` before asset catalog compilation. The owner-supplied launcher is preserved as a tracked text build input; the reconstructed `AppIcon.appiconset/Art.png` remains ignored. Icon preparation works offline and never downloads the superseded launcher.
- For Shorts replacements, download a licensed source into a temporary directory. Inspect representative frames and export a 9:16 fast-start MP4 and a matching JPEG. Upload both to a versioned Storage path and verify public HTTPS, SHA-256, and MP4 byte-range support before switching catalog references. Record the source, license and edits in the manifest, then remove the temporary copies. Keep image and video payloads out of Git.

## Shared icon artwork

`App/CommunityContent/IconArtwork.plist` contains text-encoded copies of the original 19 individual ImageGen assets used for navigation, toolbars, reactions, wallet diamonds, and consent. It also contains the horizontal More icon and illustrated skyline used by app-owned dialogs, available offline. The More artwork uses three mint enamel dots with gold rims; the skyline shows moonlit violet rooftops with amber windows. Both generated originals and bundled derivatives are identified by SHA-256 in the artwork manifest. The existing filled originals were verified against `Docs/Artwork.json`. The outline artwork retains the original ImageGen source and planned Storage paths in the same manifest. Using these copies for controls keeps all icon variants available on first render, including before the two outline originals are published. The application still uses the existing 48-point icon targets.


The reaction loader measures these bundled variants by their visible silhouette rather than the original padded canvas. The avatar and all icon variants share a 40-by-40-point visible presentation, including both Like and Save states. This supersedes the earlier narrower bookmark and shorter heart presentation. Source-specific content bounds exclude transparent margins and peripheral glow. UIKit prepares these display copies once in memory from the original, individually generated art; no source artwork is replaced. If the bundled images change, update and visually verify all icon content bounds together.


Verified on November 12, 2026 on Sese UI Acceptance (iPhone 17 Pro) using the current workspace build. Serial UI testing toggled and restored both reactions, confirmed acknowledged count updates and creator totals, and captured the original and toggled states. Visual comparison confirmed matching heart and bookmark footprints across states. Evidence: `/private/tmp/SeseReactionSize.xcresult` and `/private/tmp/sese-reaction-size-screens/`. The test passed with zero failures and preserved the initial reaction states.


Comments and Share use the existing hosted ImageGen PNG bytes, verified against `Docs/Artwork.json`, as bundled text-encoded data. Their original canvases are 156 by 156 and 156 by 104 pixels, with visible content bounds of 108 by 114 and 81 by 82 pixels respectively. Display normalization removes this unequal padding before mapping each shape into the same 40-point square as the avatar. No new artwork, remote write, native symbol, or button background is introduced.


The global icon standard is `Theme.iconSize` (40 points), reduced from 48 at the owner’s request. `Theme.iconTouchSize` remains 48 points for icon-only controls. All 19 app-owned icon variants are loaded from the bundled text-encoded `IconArtwork.plist` and normalized centrally by `Artwork.iconImage`. Toolbar controls, labeled actions, tab items, wallet diamonds, and both consent states use these same prepared images without independent 25/27/34/36/40/52/58-point scales. Labeled actions stack their icon above the title to preserve the fixed artwork size on narrow screens. Original PNG hashes remain in `Docs/Artwork.json`; originals have not been replaced. Backgrounds, maps, editorial images, and large profile portraits remain content imagery.


The Video options control reuses the individually generated settings artwork at the shared size instead of a small typographic ellipsis. The filled heart's low-opacity peripheral backdrop is cleared in its in-memory display copy, keeping its opaque illustration and the original source file intact. This prevents a rectangular haze from appearing over the video after content-bound normalization.


The latest owner preference is a smaller global footprint: 40 points for visible icon artwork, with 48-point touch targets. Shorts artwork and compact avatars are centered within those targets. Native tab labels use a two-point position adjustment, avoiding the clipping caused by the earlier 48-point icons and larger text offset. All icon states still share the same prepared size.
